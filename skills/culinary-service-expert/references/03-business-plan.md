# 商业计划与可重算经营模型

## 一页服务论证

明确谁在何时遇到什么困难、目前如何解决、为何会换用、由谁付费、交付成本是什么。SpicyLab 示例定位：为希望做川渝湘赣家常菜的家庭用户，把已有食材转成诚实的选菜建议，再把缺料和工艺接上。当前是产品假设与原型能力，不是已验证的付费业务。

## 商业计划书推荐结构

| 章节 | 必须回答 | 需要的证据 |
|---|---|---|
| 执行摘要 | 核心问题、方案、阶段、资金用途 | 已有项目与明确假设 |
| 行业与机会 | 为什么是这个细分任务 | 官方统计、竞品走查、访谈 |
| 用户与价值 | 谁用、谁付费、使用频次 | 行为分群、真实故事、付费实验 |
| 产品与内容 | 从找菜到做成怎样闭环 | 流程、内容规格、演示与限制 |
| 差异化 | 为什么不继续用免费菜谱搜索 | 对照任务结果，而非“AI领先” |
| 商业模式 | 如何收费、退款和履约 | 价格实验、合同、实际单位成本 |
| 获客与留存 | 哪个渠道带来持续做饭者 | cohort、激活、周使用与复用 |
| 运营与团队 | 谁试菜、谁审校、谁处理问题 | RACI、产能、内容版本与事故流程 |
| 财务 | 收入、变动成本、固定成本、现金 | 条件模型和敏感性分析 |
| 里程碑与风险 | 什么时候扩大或停止投入 | 可量化关卡、时间和责任人 |

## 收入路径的取舍

1. **订阅/进阶厨艺课程**：基础查菜与安全提示可免费；付费价值放在系统训练、菜单协作、个性化服务。不要拿必须知道的过敏信息收费。先验证重复使用，再验证付费。
2. **食材/厨具导购佣金**：标明商业关系；推荐排序不因佣金隐瞒缺料或过敏风险。佣金收入按净成交与退款后计算，GMV 不能当收入。
3. **品牌合作内容**：明确广告，评估是否损害信任；没有签约不得写已合作品牌。
4. **B2B 内容/培训授权**：需要可追溯菜谱、版本、权限和试做记录；独立估算销售周期、实施与售后。

SpicyLab 第一阶段建议只验证一个主模式。订阅是可测试方向，现有源码未实现支付、课程履约或商业数据后台。

## 单位经济

统一为人民币/月；输入含税或未税要一致。以下简化模型不含税和退款以外的会计调整：

```text
付费人数 = 月活人数 × 付费占比
订阅净收入 = 付费人数 × 月价 × (1 − 退款率)
平台支付费 = 订阅净收入 × 费率
月贡献 = 订阅净收入 − 平台支付费 − 月活人数×人均变动成本
经营结果 = 月贡献 − 固定成本 − 当月获客支出
CAC = 获客支出 / 当月新增付费人数  （分母为0时无定义）
单付费用户贡献 = 订阅净收入×(1−费率)/付费人数 − 总变动成本/付费人数
回收月数 = CAC / 单付费用户贡献  （贡献≤0时无法回收）
```

本模型把全部活跃用户的服务成本分摊给付费用户，较仅计算付费用户成本更完整；内容制作、人力、试菜、客服、云服务最低消费分别列入固定或变动成本且不重复计算。若课程按次售卖、年费预收、佣金抽成，不强行套月订阅。

示例三情景见 `assets/examples/business-scenarios.json`，全部为教学假设。基础情景：10,000 月活、3% 付费、19 元/月、3% 退款、3% 支付费率、每活跃用户变动成本 0.20 元、固定成本 20,000 元、获客支出 6,000 元，收入规模仍远不足以覆盖运营。这一结论提示先验证留存与成本，不把“有流量”写成盈利。

用 `scripts/business-model.mjs` 重算。负利润是有效结果，不能为了漂亮而删去免费用户成本、人工或内容审校。

## 12个月现金计划与敏感性

每月登记期初现金、现金流入、薪酬、研发、试菜/摄影、工具云服务、推广、税费、退款准备、期末现金。融资额从负现金峰值与合理缓冲反推，不从估值愿望反推。年度订阅现金到账与当月确认收入分别记录。

敏感性至少测试：留存下降、付费率减半、获客价格上升、内容成本翻倍、服务器/图片流量增加。粗略 LTV=月贡献/流失率仅在稳定留存、稳定贡献假设下适用；早期改用 cohort 实际累计贡献，不把公式结果当长期事实。

## 90天验证路线（规划示例）

| 阶段 | 产出 | 决策门槛示例 |
|---|---|---|
| 1–2周 | 访谈、基线任务、标准与来源表 | 能解释前三个真实失败点，非只收到“很好用” |
| 3–5周 | 12道代表菜的内容审校与核心流程 | 安全问题关闭；输入→推荐→采购任务可完成 |
| 6–8周 | 小规模家庭试用、复做记录 | 自愿重复使用；清楚知道放弃原因 |
| 9–12周 | 价格实验、渠道cohort、成本记录 | 有付费证据且单位贡献改善，再决定扩大 |

门槛由项目预算和试点样本提前确定。没有可靠保留用户、持续负单位贡献或内容安全无法保障时，缩小服务范围、调整定价或暂停扩张，不以新增功能掩盖问题。
