# 从家庭菜谱扩展到餐饮运营

只在用户要求实体餐饮、厨房培训或B2B服务时读取。本模块不意味着SpicyLab已经具备商用厨房管理、资质或经营数据。

## 标准菜谱卡与成本

标准卡应包含：菜谱版本、销售份量、毛料/净料、出成率、单位采购价及日期、调味包、设备/批次、工序、关键控制点、摆盘份量、出品时间、允许偏差、责任人和过敏原。家庭份数放大为30份要重新试制，锅体受热和持温都不是线性缩放。

```text
所需毛料重量 = 所需净料重量 / 可食净料率
原料成本 = Σ(采购计价单位下的毛料数量 × 单价)
单份食品成本 = (原料成本 + 已计入的合理损耗) / 实际可售份数
单份贡献 = 净销售价 − 食品变动成本 − 包材 − 支付/配送等变动成本
```

清楚说明损耗是否已包含在出成率，不能重复计算。干货泡发可能增重，应分别标干料采购成本与泡发净重；带骨鱼头、整鸡去骨不能按名称直接抵扣净肉。价格含税、配送、平台费与份数口径一致。

示例（纯教学假设）：需净牛肉0.25kg、净料率0.9、采购60元/kg，则该部分毛料约0.278kg、成本约16.67元；这不是当地市场报价。与调料、蔬菜、包材等相加后才形成单份变动成本。

## 菜单工程

以销量与单份贡献的真实数据区分高销量高贡献、低销量高贡献、高销量低贡献、低销量低贡献。观察期、促销和缺货要标明，不能仅凭点击热度砍菜单。价值判断还包括准备工时、台面占用、食材复用、浪费、服务定位和必要品类覆盖。

地域招牌菜可作为识别入口，家常快手菜支撑复购；食材共享降低采购复杂度，但不可为了通用酱料牺牲菜名身份或忽视过敏。毛利率高不等于整店盈利，人工、租金、设备折旧与获客仍需列入经营模型。

## 厨房服务蓝图与SOP

| 环节 | 最小记录 | 异常与责任 |
|---|---|---|
| 供应商/采购 | 供应商、品项、批次、票据、验收条件 | 来源/温控不符拒收或隔离，记录处理人 |
| 入库/贮存 | 时间、位置、状态、温控、先进先出/先到期先出规则 | 超限与过期处置，不能只在系统里改日期 |
| 备料 | 净料、器具分区、工序、人员 | 生熟交叉、过敏原交叉接触检查 |
| 加工 | 配方版本、批量、设备、适用温时检查 | 不合格批次继续处理或报废，不凭颜色放行 |
| 出品/配送 | 分装、份量、时间、包装、保存条件 | 超时温控、投诉与批次追溯 |
| 清洁/收尾 | 清洁消毒、废弃、剩余品处理与温控 | 有记录也需实际执行验证 |

具体限值从适用法规、食品类别与经验证工艺确定。本模板不自动构成HACCP计划或认证。

## 数字产品的B2B增量

门店、岗位、配方版本权限；批量成本与单位转换；供应商与批次；替代审批；培训记录；盘点差异；出品与异常追溯。多门店配方发布需要生效时间、旧版回退、门店确认及离线可读。经营数据与消费者浏览行为不同，不要沿用匿名localStorage作为正式账本。

## 运营职责

产品负责人定义任务与指标；厨艺编辑维护工艺/地域变体；食品安全负责人确认适用规则和异常处置；设计负责厨房可用性；开发负责数据一致性和审计轨迹；经营者承担实际履约与管理责任。AI可辅助结构化和检查，不能充当已经签字的负责人。
