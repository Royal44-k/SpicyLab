调用示例：

> 使用 $culinary-service-expert，为一款面向家庭用户的川渝湘赣菜谱服务制定产品方案。先给服务定位、用户故事与核心流程，明确研究证据、假设和验收条件；本次不发布网站。

> 使用 $culinary-service-expert，审查现有食材匹配与采购机制。重点检查鱼肉与鱼头、不同豆腐、干湿米粉、人数变化及已购数量，给可执行的数据规则和回归案例。

> 使用 $culinary-service-expert，完成一个赣菜宣传页brief，包括文案、地域视觉、图像要求和移动端验收；不要虚构用户成绩或自动修改应用。

技能只按任务加载对应资料，不要求每个小问题都走完整商业策划流程。

## 包内资源

共 **31个文件**：入口与UI元数据各1个、15篇参考指南、6份模板、2份结构化示例、3张历史截图、2个业务工具与1个测试脚本。

模板包括项目工作包、证据表、资产表、15条回归案例、设计令牌、海报brief。两个工具采用Node.js内置模块，无需安装npm依赖：

```powershell
# 在技能目录内执行
node scripts/business-model.mjs assets/examples/business-scenarios.json
node scripts/audit-recipe.mjs assets/examples/recipe-record.json
node --test scripts/test-tools.mjs
```

经营模型明确处理退款、支付费用、免费活跃用户服务成本、固定与获客支出；零分母/负贡献不制造虚假的盈亏平衡。菜谱工具验证数据结构与用料引用，不认证食品安全；样例仍是待试做草稿。

三个截图均原样取自项目固定版本，图注注明历史状态和限制。技能没有重复打包整套应用；全部应用资源仍在 [SpicyLab 固定版本](https://github.com/Royal44-k/SpicyLab/tree/3c5ee36c62707607a85bdb0a530493d2ac9e8963)，包含运行菜图、高清母版、历史演示截图、开发规格和说明。

## 不能外推的结论

- 独立测试与现有反例重合，不能据此保证所有食材、地域或商业模式的泛化正确性。
- 缺少真实访谈、经营流水、逐菜厨师试做和素材商用许可记录；文档将其标为假设或待验证，不补造证据。
- 本次未重跑全部浏览器/真机测试，未改代码、上传新GitHub提交或发布线上版本。历史通过记录不等同本次验收。
- 来源表披露法规全文访问限制；经营落地时仍需核对现行完整文本、业务模式与当地要求。技能不是安全认证或法律意见。
- 海报资源是文案、版式和素材要求模板，不是已经设计生成并发布的宣传成品。

按 `skill-creator` 的渐进加载方式组织资料，并通过独立情景评测检查实际决策；按完成前核验要求，以文件、脚本输出和哈希作为交付证据。
